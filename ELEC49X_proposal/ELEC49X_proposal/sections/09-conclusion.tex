\CourseSection{Conclusion}\label{sec:conclusion}

Agent skills are prose instructions that spread by copying, with no compiler to check them, and nobody yet knows whether the metrics used to judge source code mean anything for them. We propose a reproducible pipeline that calculates and validates size, churn, age, clone coverage, and readability on the GitSkills snapshot, excluding SpecMine, running skills, and causal claims about quality.

The plan is traceable from end to end: stakeholder needs (SN-1 to SN-5) lead to requirements, requirements to the functions and prototypes of Section~\ref{sec:functional-description} and Table~\ref{tab:prototypes}, and those to the tests of Section~\ref{sec:testing} and the milestones of Table~\ref{tab:proposal-milestones}. Success means delivering a validated metrics file, documented metric definitions, reproducible code, and a report stating which metrics have meaningful equivalents and how each compares with source code. A metric that fails validation is still a useful result, provided the report says so. The work is feasible on the \$0 budget because the data and tools are free, the pilots ran on a laptop, and each metric has an owner; our remaining gaps are large-scale data handling and non-parametric statistics.

The main limitations are measurement limits, not implementation risks. The readability formulas apply only to English and were not calibrated on instructions, so grades stay estimates. Copy direction is inferred from dates and may be wrong for some links, so lineage is reported with its basis and sampled by hand. The code baseline covers only the skills that bundle scripts, and the data covers only public repositories, so comparisons describe that population and not all skills. The full-dataset limits in PF-01 and PF-02 remain untested, with R3 and R5 as fallbacks. These limits narrow what SN-1 and SN-2 can conclude without blocking them; repeating the analysis on a wider code baseline or with direct measures of agent behavior would address them in future work.

Pilots on the sample have informed the size, churn, and readability methods, and dataset preparation and calculation checks (M2, M3) are in progress. The immediate next steps are finishing metric definitions (M1) and integrating the sample pipeline (M4).
