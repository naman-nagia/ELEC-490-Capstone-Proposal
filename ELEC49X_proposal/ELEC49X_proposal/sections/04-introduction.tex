\CourseSection{Introduction}\label{sec:introduction}

\CourseSubsection{MSR Challenge and Project Motivation}

The Mining Software Repositories (MSR) Mining Challenge invites researchers to investigate development practices using shared software repository datasets. The 2027 challenge provides GitSkills, a dataset containing approximately 3.8 million occurrences of agent skill files~\cite{msr2027MiningChallenge}. An agent skill combines natural-language instructions in a \texttt{SKILL.md} file with optional supporting scripts and references. The file opens with a YAML header, called front matter, whose description the agent matches against a task; the instructions follow in Markdown. Skills can spread through copying between repositories, and no compiler or type checker verifies whether an agent selects the appropriate skill~\cite{msr2027MiningChallenge}. Understanding skill duplication, revision activity, and instruction complexity could provide insight into how these artifacts are reused and maintained. However, applying standard software metrics to skills requires examining what those measurements capture and whether their interpretation remains meaningful.

Our team will use GitSkills to study how agent instructions are written, reused, and maintained in software environments. These findings could help developers and researchers identify patterns in the development and evolution of this emerging software artifact.

\CourseSubsection{Project Objective and Research Direction}\label{sec:project-objectives}

The project builds on MSR's question of whether established software metrics such as size, churn, age, clone coverage, and readability have meaningful equivalents for agent skills~\cite{msr2027MiningChallenge}. Prior work has evaluated code readability against human judgements, providing a precedent for checking whether calculated metrics reflect their intended interpretation~\cite{buse2010readability}. Applying such measurements to agent skills requires checking their suitability for natural-language instructions and any accompanying code or supporting material. The team will first define each metric, verify its calculation, and evaluate its interpretation for agent skills. Supported measurements will then be used to examine distributions and relationships, with inconclusive findings and measurement limitations reported explicitly. Potential analyses include how instruction complexity relates to revision activity and how duplicated content is distributed across skill collections. The engineering objective is to develop a reproducible pipeline that processes and validates data, calculates metrics, and produces visualizations supporting conclusions about skill development, reuse, and maintenance.

\CourseSubsection{Scope and Deliverables}

The initial scope is to explore GitSkills and assess which metrics support meaningful analysis of agent instructions. Specific research questions will be refined using preliminary results, while the core work remains metric definition, validation, and reproducible analysis. SpecMine is excluded to focus efforts on agent skills. Non-English skills will be counted and included in applicable metrics, but excluded from English-language readability scoring. The study will characterize repository artifacts and their relationships; executing skills to evaluate agent performance and establishing causal effects on skill quality are outside scope.

Deliverables include documented metric definitions, reproducible analysis code, visualizations, and a report interpreting the findings. Analyses requiring unavailable history or unsupported measurements will be narrowed or omitted, with exclusions and their implications documented. The team intends to submit to the MSR 2027 Mining Challenge, subject to having sufficiently developed and validated findings for the December 18, 2026 abstract and December 23, 2026 paper deadlines~\cite{msr2027MiningChallenge}. Otherwise, work will continue according to the capstone schedule without compromising rigor to meet the conference deadline.

A researcher will run the pipeline on a workstation using a fixed GitSkills snapshot and recorded configuration. External inputs comprise the dataset and selected repository histories; the system boundary covers data preparation through metric calculation and output generation. Operation assumes sufficient local storage and access to required histories, with batching used to manage memory limits.
